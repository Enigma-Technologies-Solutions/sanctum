How it works

Four steps, no trust required.

Paste a tool, read what it wants, approve what you're comfortable with. The sandbox does the rest.

Step 01

Ingest

Paste from the clipboard or load a file. Sanctum copies it into content-addressed storage and stamps it with a SHA-256 hash. The original is never executed.

invoice-parser.html

sha256 · 3a4b5c…e91f

Step 02

Scan

Static analysis pulls out every capability signal (camera, USB, serial, geolocation, storage, smart cards) plus the literal hostname of every endpoint.

const r = await fetch(
  "api.example.com/rates")
navigator.mediaDevices
  .getUserMedia(…)

Step 03

Approve

A permission manifest, not a dialog box. Toggle each capability. Network is per host: approve the one endpoint the tool needs and nothing else.

api.example.com
Camera

Step 04

Run

The tool opens at its own isolated origin, under a Content Security Policy built from your approvals. The OS bridge is gone before its HTML is parsed.

sanctum-tool://tool-7f3a/

connect-src https://api.example.com

Security model

Five layers, in enforcement order.

Every layer is enforced by the runtime, not by the scanner. A tool that hides its intent still hits the same walls.

sanctum-tool://tool-7f3a/

localStorage · IndexedDB · cookies

sanctum-tool://tool-c21d/

localStorage · IndexedDB · cookies

01

Origin isolation

Each tool runs at its own origin. The WebView scopes storage, cookies and service workers per origin, so two tools can never read each other's data.

default   connect-src 'none'
approved  connect-src https://api.example.com
always    form-action 'none'

02

CSP enforcement

Every fetch-type directive starts denied. Approved hosts are injected as explicit https: and wss: entries when the window is created. Nothing is relaxed unless you relaxed it.

window.__TAURI__
→ undefined

03

IPC removal

Every __TAURI__* global is deleted before the tool's HTML is parsed. The tool's capability set is empty, so a smuggled-in IPC bootstrap reaches nothing.

3a4b5c…e91f ✓ match
3a4b5c…0000 ✗ quarantined

04

Integrity check

The stored file's SHA-256 is recomputed on every launch. A mismatch quarantines the tool permanently. No prompt, no override.

scan    drives the approval screen
sandbox holds regardless

05

Static scan advisory

The scanner tells you what to approve. It is deliberately not the security control. Anything it misses is simply never granted.

New in 0.1 · Hardware

Smart cards, one applet at a time.

A tool can talk to a FIDO2, PIV or OpenPGP card, but only to the exact applet you approved. That unlocks things WebAuthn never exposes to a web page, like CTAP2 hmac-secret.

FIDO2 / WebAuthn (CTAP)a0000006472f0001

No other applet on the card is reachable

Approval names the applet.

The scan lifts literal applet IDs out of the source, so you approve “FIDO2 / WebAuthn”, not blanket access to whatever card is in the reader.

  • SELECTFIDO2 a0000006472f00019000
  • CTAP2getInfo9000
  • SELECTPIV a000000308refused

No pivoting on the same card.

Raw commands can't re-select, so a tool approved for FIDO can't reach your PIV or OpenPGP keys. Sessions close with the tool's window.

FAQ

Common questions

What counts as an “HTML tool”?

A single HTML file with its script and styles inline: the calculators, parsers, dashboards and converters AI models write when you ask for “a little tool that…”. If it runs by double-clicking an .html file, Sanctum can run it.

Does Sanctum send anything anywhere?

No account, no telemetry, no analytics. The one request Sanctum makes on its own is an update check against its GitHub releases. Updates are signature-verified in Rust against a key compiled into the app, and never install without your click.

What if a tool needs the network?

The scanner lists every literal hostname in the source. Approve the ones you trust and Sanctum adds exactly those to the tool's Content Security Policy as https: and wss: entries. Anything else, including hosts assembled at run time, stays blocked.

Can a tool hide what it does from the scanner?

It can try, and that's why the scanner isn't the security control. The scan only decides what's on the approval screen. The sandbox enforces your approvals, so a capability the scan never saw is a capability that was never granted.

Which platforms are supported?

macOS as a universal build, signed with a Developer ID and notarized by Apple. Windows as .msi and .exe. Linux as .deb, .AppImage and .rpm for x86_64 and arm64, including Raspberry Pi OS.

Why is the individual version free?

Because the sandbox is the product's promise, and a promise behind a paywall isn't one. What organizations pay for (signed policy, fleet deployment, audit evidence) is a different problem with a different buyer.

Why AGPL-3.0?

So anyone can read the code that stands between a tool and their machine, and improvements stay open. If AGPL doesn't fit how your company ships software, a commercial license is available.
